# Problem Management Business Process

## Tujuan

Mengelola akar penyebab dari incident yang berulang agar tidak terjadi kembali di masa depan.

---

## Actor

### IT Staff

- Analisis Problem
- Identifikasi Root Cause
- Membuat Known Error
- Implementasi Fix

### IT Supervisor

- Review Problem
- Approval Root Cause
- Monitoring Problem

### IT Manager

- Monitoring Problem Trend
- Approval Permanent Fix

---

## Problem Status

Open

↓

Under Investigation

↓

Known Error

↓

Pending Fix

↓

Resolved

↓

Closed

---

## Root Cause Analysis Flow

1. Incident berulang terdeteksi

2. Supervisor membuat Problem Record

3. IT Staff melakukan investigasi

4. Root Cause ditemukan

5. Sistem mencatat Root Cause

6. Known Error dibuat

7. Tim membuat Permanent Fix

8. Fix diimplementasikan

9. Problem ditutup

---

## Known Error Flow

1. Root Cause ditemukan

2. Known Error dibuat

3. Workaround didokumentasikan

4. Artikel Knowledge Base dibuat

5. User dapat menggunakan solusi sementara

---

## Permanent Fix Flow

1. Tim membuat solusi permanen

2. Testing dilakukan

3. Approval Supervisor

4. Implementasi Production

5. Monitoring hasil implementasi

6. Problem ditutup

---

## Output

- Root Cause tersedia
- Known Error tersedia
- Permanent Fix tersedia
- Problem History tersedia
- Problem Trend tersedia
- Problem Report tersedia
